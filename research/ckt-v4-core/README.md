# CKT v4 compact CPU core

This crate is the deterministic CPU reference for CKT v4. It deliberately starts
without a GPU dependency. A GPU backend may be added only after its complete
outcomes and all four per-mode track summaries agree with this crate and the JS
reference fixtures.

## Implemented milestones

- pack up to six keys from the 34-key domain into one `u64`;
- reproduce JS candidate order, staged early commit, terminal rank and cognition;
- support the traditional 21×21 and explicit four-code-top contracts;
- update changed rows through an exact collision-component incremental resolver;
- validate full and incremental results against fixtures generated by
  `tools/ckt_v4_model.js`.
- read phase-2 real fixtures one scheme/mode at a time from a compact binary
  format, retaining explicit keyboard contract and source provenance.
- generate the same rows natively from a phase-3 shared corpus plus a small
  scheme state, with inverted pinyin/auxiliary dependencies for exact updates.

The incremental resolver is correctness-first. It finds the transitive component
of rows sharing any old or new stage bucket and recomputes only that component.
This is exact because no row outside the closed component can affect membership,
winner removal or terminal rank inside it. Later optimization may replace the
component scan with corpus-specific inverted indexes without changing the API.

## Commands

From the repository root:

```powershell
just ckt-v4-rust-verify
just ckt-v4-binary-fixture "S005,L600"
just ckt-v4-binary-verify
just ckt-v4-native-corpus "S005,L600"
just ckt-v4-native-verify
just ckt-v4-native-incremental-smoke
cargo test --release --manifest-path research/ckt-v4-core/Cargo.toml
```

`Cargo.lock` is committed. `target/`, restored corpora and annealing checkpoints
are ignored. The old `rime-snow-pinyin` research scripts remain historical input;
new CKT v4 algorithm work belongs here.
