# CKT v4 第六阶段：规则拓扑能力审计

日期：2026-10-16

## 目的与复现

这份审计回答的是“现有 HTML 方案能否在统一的 `27 声母槽 × 35 韵母槽`
规则状态中无损往返并参加退火”，不是判断方案能否正向计算 CKT v4。两种能力
必须分开：特殊方案可以拥有完整逐音节码表、正常正向评分，却不能被错误压缩成
每个声母和韵母各一个键的规则状态。

复现命令：

```powershell
just ckt-v4-capability-audit
```

命令从主目录 HTML 重建 `research/.cache/ckt-v4-all-schemes.json`，再生成并校验
被忽略的 `research/.cache/ckt-v4-capabilities.json`。输入版本为
`ckt-v4-scheme-state-2`，输出版本为 `ckt-v4-capability-audit-1`；物理键全集固定为
`ABCDEFGHIJKLMNOPQRSTUVWXYZ[]\;',./`。

本次输入 HTML 的 SHA-256 是
`348d1b271083a2d0bd76a67678d5b5978b4767b2e51fe90fbedb18fe2f702c79`。
报告保留这个哈希，因而 HTML 发生变化后旧统计不会被误认为同一次实验。

## 840 个方案的结果

| 原因码 | 数量 | 含义 |
|---|---:|---|
| `supported` | 515 | Common399 能按规则槽精确往返，可进入规则退火 |
| `common_final_split` | 237 | 同一规则韵母槽在不同音节中落到多个键 |
| `common_head_split` | 75 | 同一规则声母槽在不同音节中落到多个键 |
| `forward_invalid` | 13 | 逐音节正向码本身不完整或非法 |

13 个 `forward_invalid` 均是当前 HTML 中 `MX9-01` 至 `MX9-13` 的空码记录；
这不是规则拓扑判定造成的拒绝。其余 827 个方案都可建立正向 `SchemeState`。

规则退火支持矩阵如下。这里的“支持”是行为审计结果，不按方案 ID 或尺寸硬编码：

| 容量 | HTML 总数 | 规则退火支持 | 不支持 |
|---|---:|---:|---:|
| 21×21 | 301 | 267 | 34 |
| 21×26 | 327 | 231 | 96 |
| 21×28 | 17 | 17 | 0 |
| 23×23 | 63 | 0 | 63 |
| 25×30 | 68 | 0 | 68 |
| 26×26 | 58 | 0 | 58 |

`S005-NF`、`SNF4-M36-AE-07`、`SNOW-SHENYUN-21X28-SHAPE`
分别作为 21×21、21×26、21×28 的回归哨兵；recipe 要求三者持续为
`supported`。

## 唯一性与 421 音节边界

能力审计先检查 399 个常用音节（Common399）的规则槽往返；只有 21×21 和
23×23 使用 `allow_collisions`，其他尺寸使用 `require_unique`。这条政策属于尺寸
合同，但“能否规则分解”仍由实际码表行为决定。当前 515 个支持方案全部通过
Common399 往返。

另有 22 个扩展音节只做独立诊断，不反向否决规则退火。本次 515 个支持方案的
`extensionRoundTrip` 都是 `false`，说明冻结语料与规则状态的优化边界确实是
Common399；不能为了追平扩展码而把每音节自由变量偷偷带入退火。

## 特殊拓扑的明确边界

`N095`（23×23）和 `H37`（25×30）都满足 `forwardScore=true`，所以它们仍可按
完整码表计算 CKT v4；二者分别在韵母槽 0（音节索引 345）和韵母槽 31
（音节索引 193）出现上下文分支，因而是 `common_final_split`，并明确标记
`regularAnneal=false`。

第六阶段按已确定的范围不为这两个特例编写专用拓扑适配器，也不从最终码表猜测
其生成规则。这个限制不影响正向 CKT v4、公平比较或以后增加经验证的专用适配器；
它只阻止当前规则退火器把不可表达的拓扑误当作自由度更大的普通方案。
