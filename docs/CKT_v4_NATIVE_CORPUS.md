# CKT v4 阶段 3：共享语料与 Rust 原生行生成

状态：共享只读语料、独立方案状态、Rust 原生联合池行生成和固定拓扑倒排更新已经形成可运行闭环；约束感知的退火状态/提案层仍待接入。

## 为什么不能继续保存逐方案行

阶段 2 的 68.6 MiB 紧凑行夹具解决了 JSON 内存放大，但每增加一个方案仍会重复约 29 万行及全部阶段码。退火时实际变化的是很小的布局状态，字词、拼音序列、声调、字形槽、笔画候选和频率都不应重复。

阶段 3 因此拆成：

```text
5.13 MiB 共享语料模板 + 每方案约 6 KiB 状态
                       ↓ Rust 原生实例化
        21×21 或四码顶的完整联合池阶段行
                       ↓ 精确解析
               四轨 CKT v4 / 综合分
```

共享模板由 `tools/export_ckt_v4_native_corpus.js` 从与阶段 2 相同的 HTML、冰雪主词典和笔画词典生成。文件头记录三项 SHA-256、34 键字母表、词频质量、模板数量和扩展键投影。具体方案另存为 JSON，只含 ID、键盘口径、五个辅码键和 421 项双拼码表。

## 模板字段

- 单字：稳定 ID、拼音索引、声调、权重、前两个冰雪字形槽、笔画首类集合；
- 二至四字词：各字拼音索引、声调、权重、前两字首字形槽；
- 不保存词条正文，因为竞争排序和 CKT 汇总不读取正文；
- 二字词保留全部合格项，三/四字词沿用统一词频质量截断；模板顺序与 JS 权威适配器完全一致。

Rust 根据显式合约生成阶段：

- 21×21 三字词保留 `AAA→AAAB→AAABB` 独立池；二/四字词共享四至六码池；
- 非 21×21 三字词走 `AAA→AAAU→AAAU+辅码`，从四码起与二/四字词共享池；
- 键道和三拼分别按现行辅码顺序构造；候选码仍按 JS UTF-16 词法序去重和排序；
- 全部物理键使用 34 键全集，单码仍按 6 bit 打包。

## 倒排增量更新

每个生成模式同时建立：

- `pinyin index → row indices`；
- `five auxiliary slots → row indices`；
- `row index → corpus template source`。

候选状态与当前状态比较后，倒排表给出直接受影响行。`generate_updates` 只从相应模板重建这些行，再交给阶段 1 的精确碰撞组件解析器。未被倒排集合覆盖的行在验证中必须逐行不变。

当前增量 API 有意限定为固定拓扑：键盘口径/合约不变，拼音码的 `Some/None` 可用性不变。21×21 与 21×26 之间的转换属于另一个搜索空间，应重新生成；不能伪装成局部交换。当前方案状态是最终 421 项码表，尚未表达声母、韵母共享映射和容量等退火约束；后续约束感知提案器必须先生成合法码表，再调用本层差分。

## 等价性门槛

`verify-native` 把 Rust 原生生成的每一行与阶段 2 冻结行夹具比较。比较包括：

- 行数、顺序、ID、词长类型、权重和基础码长；
- 每个阶段的长度、候选池、候选码数量、顺序和打包值；
- HTML 来源哈希、字母表与方案 ID。

2026-10-16 的真实验证：

| 方案 | 合约 | 模式 | 行数 | 逐行结果 |
|---|---|---:|---:|---|
| S005 | 21×21 | 键道 | 289,644 | 完全相同 |
| S005 | 21×21 | 三拼 | 289,649 | 完全相同 |
| L600 | 21×26 四码顶 | 键道 | 289,644 | 完全相同 |
| L600 | 21×26 四码顶 | 三拼 | 289,649 | 完全相同 |
| SNOW-SHENYUN-21X28-SHAPE | 21×28 四码顶，含 `,.` | 键道/三拼 | 289,644 / 289,649 | 完全相同 |
| H37 | 25×30 四码顶，含 `[;'/` | 键道/三拼 | 289,644 / 289,649 | 完全相同 |

后两项专门覆盖非标准键数及标点物理键，确认原生适配器没有把键域暗中限制为 26 个字母或固定 21×26。

固定稀有拼音索引 `376↔44` 的真实交换每模式直接影响 43 行；只重建这些行耗时约 0.04–0.08 ms。精确碰撞闭包为 S005 510 行、L600 494 行；增量结果、全量重算和回滚全部一致。该数字只是确定性冒烟样例，不代表常规声母/韵母交换的影响规模。

Rust 原生正向评分得到 S005 `10.000000000`、L600 `9.710970555`。本机对两个方案、两个模式从共享基底生成并评分约 3.6 秒，25 ms 采样峰值工作集约 171 MiB。它不包含一次性的冰雪 YAML/HTML 预编译时间。

## 复现

```powershell
# 阶段 2 冻结行夹具需先存在，用作独立裁判
just ckt-v4-binary-fixture "S005,L600"

just ckt-v4-native-corpus "S005,L600"
just ckt-v4-native-verify
just ckt-v4-native-incremental-smoke
just ckt-v4-native-score
```

共享基底、方案夹具、冻结行夹具均位于被忽略的 `research/.cache/`，不会污染 Git。格式或模型变更后必须重新导出，不应把缓存当成来源事实。
