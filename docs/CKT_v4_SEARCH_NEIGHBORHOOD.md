# CKT v4 阶段 5：扩展搜索邻域与人体工学护栏

状态：Rust CPU 退火器已从第 4 阶段的安全换位轨道扩展为十类合法性过滤提案；能够改变声韵分组、引入 34 键全集中的空闲键并替换辅码键。M/D/V 可作为显式硬护栏，CKT v4 仍是护栏内唯一退火目标。GPU 后端继续冻结。

## 十类提案

检查点中的 `proposalCounts` 按以下固定顺序计数：

1. 五个辅码槽换位；
2. 单个辅码键替换为空闲键；
3. 已用声母物理键全局换位；
4. 已用声母键整体迁移到空闲键；
5. 已用韵母物理键全局换位；
6. 已用韵母键整体迁移到空闲键；
7. 单个声母组迁到另一已用键；
8. 两个声母组交换；
9. 单个韵母迁到另一已用键；
10. 两个韵母交换。

第 2、4、6 类会从完整 34 键域 `ABCDEFGHIJKLMNOPQRSTUVWXYZ[]\\;',./` 选键。标点不是只允许出现在某个硬编码尺寸中；最终是否合法由方案容量、辅码互斥和 Common399 规则共同裁决。

零声母 `A/E/O/W/Y/YU` 在一个种子中已经合并的等价组会作为整体移动或交换。因此一次退火链保留种子的零声母结构族，不会在同一链里悄悄把“合并 Y/YU”改成“拆分 Y/YU”。不同结构应使用相应种子分别开链，再比较同口径结果。

每个随机候选最多尝试 256 次。候选必须同时满足：

- 声母和韵母的实际用键数等于声明容量；
- 五个辅码键互异且与声母域互斥；传统 21×21 中还必须与韵母域互斥；
- 仅无飞 `21×21`、`23×23` 可不满足 Common399 唯一，其他尺寸必须唯一；
- 可选 M/D/V 上限。

非法尝试不会进入 CKT 评分，但会累计到检查点的 `invalidProposals`。严格唯一的 21×26 种子中，“单声母组直接换组”可能没有任何合法一步邻居；这不是放松唯一约束的理由，后续应增加成对或环状复合提案。

## M/D/V 的来源与使用

三项诊断按冻结 R11 replay 的 `opt.py`、`search_engine.py` 和 `r5_search.py` 重建：

- `M`：普通声母偏移、卷舌声母、A/E/O 载体数、W/Y/YU 规则及非本位韵母链接的旧记忆量口径；
- `D`：18 个单字母普通声母偏离本位键的数量；
- `V`：`a/e/i/o/u` 五个单字母韵母偏离本位键的数量。

`--max-memory`、`--max-d`、`--max-v` 是可选硬约束，不进入 CKT v4 公式。默认不启用，避免用某个旧实验的任意阈值暗中偏袒所有尺寸；正式对比时必须在结果中连同阈值一起报告。`SNF4-M36-AE-07` 的 Rust 重建值为 `M/D/V=36/3/0`，与旧方案名和研究口径相符。

示例：

```powershell
just ckt-v4-anneal-guarded "SNF4-M36-AE-07" 100 36 3 0 "research/checkpoints/21x26-M36-D3-V0.json"
```

## 增量性能修复

阶段 4 的增量解析器曾为每个替换行扫描整个约 29 万行语料以检查 ID 唯一性，复杂度为 `O(kN)`。固定拓扑更新实际上要求“同一索引仍是同一稳定 ID”，所以阶段 5 改为逐索引相等检查，复杂度为 `O(k)`，并新增错误 ID 的拒绝测试。

同一个 21×21 单韵母移动案例：

- 修复前：942 个直接变化行/模式、碰撞组件最多 6,001 行，约 18.6 秒；
- 修复后：相同直接行、组件和得分，含最终全量审计约 2.5 秒。

小于等于 1,024 个直接变化行/模式且不超过该模式总行数的 8% 才尝试增量；更大的提案直接走全量状态。检查点同时记录跨模式累计直接行、单模式最大直接行与碰撞组件行数，便于在目标台式机上重新标定阈值。

## 验证结果

- Rust：7 个库单元测试、3 个 JS 参考集成测试全部通过；严格 Clippy 无警告；
- 21×21 十类提案均完成一次端到端评分和全量审计；
- 21×26 除不存在合法一步邻居的单声母组移动外，其余九类均生成合法方案并完成全量审计；
- 21×26 带 `M≤36、D≤3、V≤0` 的两步链保持 `36/3/0`，分数从 `9.269214672` 到 `9.191734679`；这是路径冒烟结果，不是收敛后的新冠军；
- 21×28 真实种子完成一步扩展邻域评分，继续满足 Common399 唯一；
- 检查点绑定方案、参考、总步数、温度、提案策略和 M/D/V 护栏，避免不兼容恢复。

## 下一步

1. 为严格唯一域增加成对/三环复合移动，减少 21×26 的非法提案率；
2. 为 23×23 与 25×30/34 键方案定义各自可审计的规则拓扑适配器；
3. 把 MX、手指负载等旧指标作为显式可选护栏或多目标输出，不改写 CKT v4 主公式；
4. 增加多种子调度与 Pareto 保留，避免只保存单一最低 CKT 而丢失 M/D/V 和人体工学前沿；
5. 在目标 R7 59xx / 64 GiB 机器长跑 CPU 基线后，再决定 GPU 批量后端。
