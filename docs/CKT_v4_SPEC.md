# CKT v4：跨口径补全、联合候选池与认知成本规范（原型 2）

状态：**已作为情景列进入主 HTML，与 v3 并列但不替换 v3**。本规范把已经由代码和测试确认的部分，与尚待人体实验标定的假设分开。现阶段不得把 v4 情景分描述成最终人体实测值。

## 1. v4 为什么不能只是替换一张上游当量表

CKT v3 有四个会实质改变排序的问题：

1. 内嵌的是上游旧快照；上游当前提交 `e37cbcfe454f872f05df7b37c686be0b6974cf19` 已采用六个段角色、上下文错误率和新的部署集成模型。
2. 文档声称二字词与四字词同台，v3 实现却逐词长调用 `scoreCohort`，没有发生跨词长竞争。
3. 非 21×21 的三字词实际走 `AAA → AAAU → AAAUB → AAAUBB`；只有未在 `AAA` 直出的残余项进入四码联合池，与 `AUAU` 二字词和 `AAAA` 四字词竞争。
4. v3 的 `τ/α₁/α₂` 同时混合了物理动作、辅码回忆、视觉确认和选重决策。上游当量只能支持其中的物理击键和普通误击恢复，不能证明视觉认知成本。

此外，v3 页面 payload 的 `data.words` 是两个外部 6 万词表的并集 92,233 项；`lexicon & 1` 过滤后实际只覆盖约 6 万项，并非文档所说的冰雪全量约 13 万二字词。

## 2. 编码合约与候选池

记 `A` 为声母小集合，`U` 为全键集合中的韵母/路由键，`B` 为五个辅码键。

### 2.1 传统 21×21 合约

| 对象 | 路径 | 候选池 |
|---|---|---|
| 单字 | `AA → AAB → AABB` | 单字独立池 |
| 二字词 | `AAAA → AAAAB → AAAABB` | 四、五、六码词池 |
| 三字词 | `AAA → AAAB → AAABB` | 三字词独立池 |
| 四字词 | `AAAA → AAAAB → AAAABB` | 与二字词共享四、五、六码词池 |

所以 21×21 的联合竞争是 `word2 ∪ word4`；三字词的 `AAAB` 使用小集合 `B`，不是 `AUAU/AAAA` 的同一输入语法。

### 2.2 四码顶合约（21×26、21×28、25×30、以及采用相同语法的其他口径）

| 对象 | 路径 | 候选池 |
|---|---|---|
| 单字 | `AU → AUB → AUBB` | 单字独立池 |
| 二字词 | `AUAU → AUAUB → AUAUBB` | 四、五、六码词池 |
| 三字词 | `AAA → AAAU → AAAUB → AAAUBB` | `AAA` 先独立提交；残余项进入四、五、六码词池 |
| 四字词 | `AAAA → AAAAB → AAAABB` | 四、五、六码词池 |

因此四码联合池是：

\[
P_4 = \text{word2} \cup \operatorname{residual}_{AAA}(\text{word3}) \cup \text{word4}.
\]

早期已提交的 `AAA` 三字词必须从后续池移除。实现必须逐阶段解析候选，而不能把所有词长分别统计后再相加。

口径分类必须来自明确的编码合约。当前数据只有 21×21 与“四码顶”两类；未来若出现不同语法的 30/34 键方案，应新增合约，不能仅凭键数猜路由。

## 3. 单项成本

对字词项 `i`，令 `s*(i)` 为它首次成为首选的阶段；若所有阶段都不是首选，则取终止阶段并保留真实候选序号 `r_i`。在各阶段中先按冰雪词频降序；完全同频时使用语料适配器生成的稳定 ID 兜底，保证所有方案确定性一致。该兜底不是对真实输入法同频候选顺序的实测声明。

### 3.1 物理层

\[
M_i = M_{\mathrm{upstream}}(c_{i,s^*}).
\]

- 2、3、4 键：直接采用上游当前六角色段当量，已含普通误击概率乘实测恢复时间。
- 5、6 键：上游明确只验证到四键。v4 原型用滚动四键上下文延续六角色段表，并标记 `exact=false`；这是外推，不是实测。
- `[ ] \\ '` 等非上游 30 键：使用页面已有的 donor 混合及距离守卫，并标记 `projected=true`。30/34 键方案不能与原生 30 键同等声称“实测”。

### 3.2 认知层

`AAAU` 的 `U` 是编码路由键，不是辅码回忆；它不计 `α₁`。只有其后的 `B` 才是第一辅码。

令 `b₁,b₂` 表示实际使用第一、第二辅码，候选页大小为 `P`。候选表按排名顺序扫描时，目标排名 `r` 之前有且仅有 `r-1` 个候选需要排除；进入目标所在页之前需要 `floor((r-1)/P)` 次翻页：

\[
A_i = \alpha_1 b_{1,i} + \alpha_2 b_{2,i}
 + \mathbf 1[r_i>1]\left[
 \tau_0 + \beta(r_i-1)+\gamma_{sel}
 \right]
 + \gamma_{page}\left\lfloor\frac{r_i-1}{P}\right\rfloor.
\]

其中：

- `α₁/α₂` 是辅码检索和确认成本，不再重复计算已经在 `M_i` 内的物理按键时间；
- `τ₀` 是发现“首选不是目标”的固定决策成本；
- `β` 是每排除一个更高排名候选的视觉扫描成本；它不在首屏末尾封顶，因为翻页前的候选同样已经被排除；
- `γ_sel/γ_page` 是选重动作和翻页动作。

当前默认工程先验取 `α₁=300 ms, α₂=300 ms, τ₀=600 ms, β=50 ms/候选, P=9, γ_sel=0, γ_page=300 ms`。于是第 2、9、10、11 名的纯选重认知成本分别为 `650/1000/1350/1400 ms`，跨越第 9→10 名时会同时增加一次扫描和一次翻页。`β=50` 与 `γ_page=300` 是保守、透明、可覆盖的情景系数，不是从上游运动实验反推的测量常数。

历史兼容场景仍可精确回放：取 `β=γ_sel=γ_page=0`，即恢复 `600·I(r>1)`。页面现有 `τ` 滑块只改变 `τ₀`，视觉扫描与翻页使用结果 payload 中明确记录的默认值；这避免让一个滑块同时偷偷改变三种不同机制。

轨道紧凑统计保存三项彼此不可替代的充分量：`P(r>1)`、`E[r-1]` 和 `E[floor((r-1)/P)]`。其中 `E[r-1]=E[r]-1` 可由平均终态排名交叉核验；翻页期望不能从平均排名恢复，必须逐项计算后聚合。这样网页无需保留全部候选明细，也能精确实时重算 `τ₀` 情景。

总成本为：

\[
E_i = M_i + A_i.
\]

## 4. 轨道均值与综合分

模式 `m∈{键道形码, 三拼调码}`，词长 `k∈{单字,二字,三字,四字}`。轨道内采用冻结冰雪频率 `q_i`：

\[
T_{m,k}=\frac{\sum_{i\in(m,k)}q_iE_i}{\sum_{i\in(m,k)}q_i}.
\]

综合分保留 v3 的 S005 锚点和四次幂短板惩罚：

\[
C_{v4}=10\left[
\frac{\sum_{m,k}w_k\left(T_{m,k}/T_{m,k}^{S005}\right)^4}
{\sum_{m,k}w_k}
\right]^{1/4}.
\]

默认场景仍用 `w=[1,3,1,1]`，因为它来自既有 5,000 字最优切分实验；但它不是普适语言学常数。发布结果必须附带至少一种更偏单字/二字的盲打场景，并报告名次是否稳定。任何参数下 S005 必须严格等于 10。

## 5. 冰雪语料冻结策略

审计文件见 `CKT_v4_CORPUS_AUDIT.json`。当前可复现结论：

- 单字成员：8,095 个通用字；其中 6,263 个有正观测频率，1,832 个频率为零。
- 二、三、四字词只接受平台冻结 Common399 音节，以保证每个合格方案都有同一可编码输入域；精确数量由审计生成器写入 JSON，不在规范中手工固化。
- ext 与 Tencent 各条权重均固定为 100，不能与 base 的分级权重混合解释成统一自然语料频率。

因此建议：

1. 主分数统一使用冰雪 base，冻结文件 SHA-256；三、四字词按各自累计 99% 频率质量截取，不用任意的 Top 15,000。
2. 8,095 单字全部进入覆盖审计；频率主分只用正权重 6,263 字，另给 8,095 字等权鲁棒性轨道。
3. 25 个固定一简作为“直接提交覆盖”单列。它们对所有方案相同时不混入补全能力分母，避免用大量共同零成本稀释差异。
4. ext/Tencent 只做长尾覆盖、污染和最坏桶压力测试，不进入 headline 加权分。
5. 同一字词的多音读法目前按“词+读音”条目保留。正式 v4 发布前应补一项敏感性测试：与“同词合并、读音作为可选编码”口径比较排名稳定性。

所以，“全用冰雪词库”是目前最一致、最易冻结的选择；但“把冰雪所有文件的 weight 都当统一词频”并不科学。

## 6. 验证门槛

v4 替换 v3 前至少满足：

- 合成测试覆盖：21×21 二/四字联合；21×21 三字隔离；非 21×21 `AAA` 早提交；残余三字进入四码联合池；终止候选序号；S005=10。
- 上游快照记录 commit、产物版本与 SHA-256；2–4 键原生范围和 5/6 键外推范围分别统计。
- 全 840 方案跑完后，分别在 95%、99%、99.5% 三/四字频率质量下报告 Spearman、Top-N 交集和前沿方案名次变化。
- 对认知参数做情景网格，报告排名对 `α₁/α₂/τ₀/β/γ_page` 的敏感性；必须包含历史 `β=γ_page=0` 场景，不得只公布一组偏好参数。
- 21×21、21×26、30/34 键每类至少选已知前沿与反例，人工复核具体碰撞桶。
- 在认知实验完成前，页面名称应为“CKT v4 原型/情景分”，不能写成“实测认知当量”。

## 7. 仍需采集的实验

上游测速任务只呈现固定 2–4 键串，无法识别辅码回忆和候选视觉搜索。建议新增被试内随机实验，分别操纵：

- 0/1/2 辅码；辅码可预知与需要看屏确认；
- 候选序号 1/2/3/5/9/10+；是否翻页；
- 目标词频、同码候选数量、目标是否在首屏；
- 21×21 与 `AAA→AAAU` 路由提示。

记录首次按键、辅码间隔、选重反应时间、误选与回退。用参与者随机截距/斜率的分层模型估计 `α₁/α₂/τ₀/β/γ`，并保留个人化参数；不要从现有运动模型反推这些系数。

## 8. 复现入口

```powershell
# 1. 冻结语料规模、阈值和文件哈希
node tools/build_ckt_v4_corpus.js --snow "D:\path\to\rime-snow-pinyin" --output docs/CKT_v4_CORPUS_AUDIT.json

# 2. 上游完成其标准流水线后，导出 Node 可读的六角色表（本地产物被 gitignore）
python tools/export_ckt_v4_upstream.py --upstream "D:\path\to\better-keystroke-timing" --output tools/ckt_v4_upstream_role_tables.json

# 3. 路由、认知分层、S005 锚点及 34 键投影单元测试
node --test tests/ckt-v4-model.test.mjs

# 4. 代表方案正式 99% 频率质量验证；可用 --ids 增减方案
node tools/score_completion_ckt_v4.js --snow "D:\path\to\rime-snow-pinyin" --mass 0.99 --ids "S005,L600,SNOW-SHENYUN-21X28-SHAPE,H37" --output docs/CKT_v4_PROTOTYPE_RESULTS.json

# 5. 全量生成采用小批次串行：推荐每个子进程只算 5 项后退出，以时间换空间
#    --compact 只保留 HTML 实时重算所需统计量；下一批把 offset 增加 5
node tools/score_completion_ckt_v4.js --all --offset 0 --limit 5 --mass 0.99 --no-cross-audit --compact --quiet --output part-000.json

# 6. 合并分片、核验 840/840 覆盖、保存全方案紧凑结果、写入 HTML payload，并产出滑杆敏感性审计
node tools/integrate_completion_ckt_v4.js --parts "D:\path\to\parts" --results docs/CKT_v4_ALL_SCHEMES_RESULTS.json --audit docs/CKT_v4_ALL_SCHEMES_VALIDATION.json

# 7. 若复用旧全量运动结果，只补算排名/翻页充分统计：Rust 每 50 项退出释放堆，MX9 用 JS 回退
just ckt-v4-native-corpus
just ckt-v4-capability-audit
just ckt-v4-rank-stats
just ckt-v4-rank-fallback
just ckt-v4-rank-prepare
node tools/integrate_completion_ckt_v4.js --parts research/.cache/ckt-v4-rank-aware-parts
```

评分器启动时会审计全部 840 个页面方案的物理键域和 Common399 完整性；遇到未声明键或 Common399 缺码立即失败，不会静默折叠。
全量候选可用 `--all`；若只做全量排名、不需要逐方案跨词长反事实审计，可加 `--no-cross-audit` 降低运行时间和内存占用。
排名统计入口固定使用 50 项独立子进程，不能改成长寿命全量进程；准备器会校验所有分片 offset 连续、来源哈希一致、840 项无重漏，并把 6,720 条新旧平均终态排名逐轨比对后才允许集成。
