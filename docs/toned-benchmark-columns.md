# 带调 21×21 的逐列 benchmark 适配

带调方案使用实际 `pinyin+tone → 两键` 映射。通用表中的指标按其本列原有语义
计算，原生四轨 CKT-T v5/v5.1 另外保留，不再拿字轨完成时间替代裸音节时间，
也不把四轨峰值放进“20合同最高”列。

## 同一列保留的量

| 列／系列 | 带调适配 | 保留的原公式与边界 |
| --- | --- | --- |
| A7E v1～v4 | 每条既有合同以实际带调两键组成编码；已进入主码的声调不重复追加 | 每版本原轨权重、E34／geometry 各半、冻结参考前沿、四阶广义均值 |
| A7E v5 | 同上，逐条完整码串计算旧 CKT tensor | 原20合同权重、旧 CKT 长码保护与冻结基线；不替换为 CKT-T |
| v6-CW150 | 字词两类的同轨 `CKT+150×非首选率` | 原字词平衡权重、S005 各轨参考、四阶广义均值 |
| v4-C | 同一带调轨的公开 Chen 键对代价 | 原 v4 几何半权重和冻结基线 |
| 当前环境 | 实际声调两键＋所请求的形辅；已含调信息的 T/Ti 合同不重复调码 | 已应用的数据集、形源、词库、频率／等权、共同集、顺序、模型与边界 |
| S2右小指 | 裸带调音节主码的右小指击键比 | 音节权重和实际击键分母，不使用单字终码 |
| 左／右小指20合同最高 | 对原20合同逐轨求相应手指键集合负担，再取最大 | 逐轨击键分母和原手指键集合 |
| 含形辅主行下限 | `min(C4-Snow.home, WX-Snow-12.home)` | 完整两形辅，非逐步补全后选码 |
| 含辅上下差 | `max(C4.upper−lower, WX12.upper−lower)` | 单字／二字词两项独立统计，保留正负号，单位 pp |

| 裸二键唯一 | 不同两键码数量／合法带调音节数量 | 无调列同样计不同码数；分母是音节数，不是 21×21 容量 |
| S2规则补全 | 对碰撞桶内所有音节追加同宽 base5 后缀，包括首选 | 原 S2-5SUF 桶排序、后缀宽度、`toneKeysByTone` 物理枚举顺序和旧 CKT；此处后缀是编号，不是重复调信息 |
| 八条 B 路径 | 原字词集、主码和两步信息后的频权非首选率 | Common8095 字集和 Snow-common 二字词；三拼去掉已经编码的调步骤，保留纯笔画步骤 |
| 消歧补全 v1／固定／v2 | 同一原字词集，各阶段首选判定，实际停止时码串 | 各代 tensor、S005 对应版本、字:词=1:2、v2 首辅／次辅认知参数 |
| 消歧补全 v3 | 原三／四字前15000条语料、独立池 | 原 native-v2 运动表和 1:3:1:1 词长权重；不替换为生产优化辅序 |
| 消歧补全 v4 | 原99%频率质量语料、共同399过滤、联合池和路由 | 原上游运动表、逐阶段竞争、候选排名／翻页、S005、1:3:1:1 权重与滑杆参数 |
| 旧 v5-S | 每轨 `旧CKT+τ×非首选率` | 原20合同权重与0/150/300/600 ms四档冻结基线；其他 τ 明确显示600ms冻结档，悬停列出全部四档，不外推缺失的历史参考 |
| 字词混合 ms／汉字 | `(T单字+2×T二字词)/5` | 原“每项”权重与输出汉字分母；预测速度 `60000/ms每汉字` |
| 音节／字形／词形非首选 | S2、完整 IRXX、完整 IRIRXX 各自桶内频权漏选 | 各自的对象、完整编码与分母；不混入最终逐步补全选重率 |
| 五档跨族碰撞 | 同一三词典与全局词频截点，保留原始声调 | AUAU／AAAU／AAAA 标准四码对照合同、首选规则、Top500/1k/2k/5k/10k；不是原生三字简码输入回放 |

仍保留，因此各版本的历史定义不变。这里比较的是“在相近任务中完成相应信息”的
带调适配指标，不表示带调／无调完成了完全相同的信息任务。

## 音节权重、规则与偏移

S2 的原 common399 每个拼音质量保持不变。在该拼音内按冻结共同单字的声调频率
分摊到合法调音节；没有任何观测调频时才在合法声调间等分。合法但未观测的调
保留为零频条目，不虚构词频。等权环境则按合法调音节等权。

FA-1-T 使用原四种拆分模板，LU-v1r-T 使用原五种模板和规则支持表；区别是将韵部
条件化为 `(韵部, 声调)`。FA 仍计算每组映射到最常见物理键的频权比例；LU 仍使用
55% 因子一致、30% 韵部支持、15% 声类规则性的公式。合并在同一调区的不同声调
视为同一韵部的兼容合并。代码同时在无调 S005 上复现原 LU 和 FA 结果。

V 仍计 a/e/i/o/u 五种普通韵类中发生原键偏移的类别数：任一合法声调的第二键离开
该元音同名键，就将该韵类计一次；沿用 j/q/x/Y 后 u 还原为 v 的原记账规则。
它不等于韵组数量或调区数量。D 仍计普通声母
首键偏移类别。M 保留明确命名的 M-T1 规则关联账及守门值，避免把调区规则数量
伪装成无调 M-R2 映射边数。

## 实现与复现

`tools/toned_benchmark_metrics.js` 是浏览器与离线评测共用的合同适配器。
`tools/score_toned_benchmark_columns.js` 直接加载发布页原 Engine7／CKTEngine，
并调用原补全造码与竞争引擎，输出独立的逐列审计块 `snowJiandao.columns`。
`tools/toned_rule_metrics.js` 实现可复核的 LU／FA／V 扩展。

表格在最内层 `uxTable` 边界加入带调行，此时其他渲染器已插入 D/V、负载、
固定五辅等列；所有单元格由最终表头取值，并带数值属性供排序及 CSV 导出。
列折叠也计入带调行，避免仅因为无调行的样本数／键数相同而隐藏实际有差异的列。
未知列适配会报错，不能静默填“不适用”或拿邻近属性充数。

运行 `just snow-jiandao-benchmark` 重算并更新本地 HTML，
`just snow-jiandao-benchmark-test` 验证公式和表格联动；
`python -m unittest discover -s tests -p test_toned_benchmark_columns.py` 验证带调碰撞语料。
原四轨生产分与键盘筛选功能均保留。HTML 与生成的审计 JSON 为被忽略的本地产物。
