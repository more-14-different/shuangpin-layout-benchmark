# CKT v4 Rust 紧凑 CPU 内核：阶段 1—6B 进展

状态：CPU 参考内核、原生语料生成、约束感知退火器、十四类规则搜索邻域、全方案能力审计和追加式精确前沿均已形成闭环。增量四轨汇总、拒绝回滚、v9 检查点恢复、M/D/V 护栏、复合 move 及大提案的全量自动回退已经验证。GPU 后端尚未创建，也不得在以下一致性门槛失效时接入。

## 仓库边界

新算法位于 `research/ckt-v4-core/`。冰雪仓库的旧 v3 研究脚本继续保留其历史位置，因为它们依赖冰雪根目录词典、冻结 R11 replay 和多组同级 Python 模块；机械复制 53 个入口脚本会得到不可独立运行的副本。今后的 v4 内核、退火接口和性能优化以本仓库为准。

构建产物 `research/ckt-v4-core/target/`、大型真实夹具 `research/.cache/` 和退火检查点 `research/checkpoints/` 均被 `.gitignore` 排除；`Cargo.lock` 纳入版本控制。

## 已实现

1. 34 键统一编号，每个键 6 bit，最长六码打包进单个 `u64`；前导零键不会丢失。
2. 与 JS 相同的词频降序、UTF-16 ID 兜底、逐阶段早提交、终态名次和等成本码选择规则。
3. 传统 21×21 与显式四码顶合约，包括非 21×21 的 `AAA→AAAU` 残余三字词联合池。
4. 上游六角色 `float32` 表、四键原生范围、五/六码滚动窗口延续，以及扩展键 donor 混合/距离守卫。
5. 认知成本与四轨汇总，保留运动、认知、首/次辅码率、选重率、终态名次和平均码长。
6. 精确增量解析器：替换若干行后，闭合其旧/新阶段碰撞桶的传递组件，只重算该组件；支持回滚及随时与全量重算比较。
7. 67 维规则布局、分尺寸 Common399 合法性、单线程退火和确定性检查点；直接影响超过每模式 1,024 行或 8% 时自动使用更快的全量候选状态。
8. 十四类提案覆盖整键、单组、空闲键及保持容量的成对/三环重分组；候选在大型联合池评分前依次通过结构、Common399 唯一性和 M/D/V 护栏。
9. v9 检查点按提案类型持久化提出、结构拒绝、唯一性拒绝、护栏拒绝、评分和接受次数，并验证固定种子的中断恢复逐字节一致。
10. 追加式 JSONL 候选日志不在 writer 中保留历史；独立归并器使用未舍入 CKT/M/D/V 生成确定性精确 Pareto 前沿。

当前增量策略首先保证正确性。若某个语料图形成巨型连通分量，它会安全退化为大范围重算；后续需以活跃桶依赖和语料倒排表缩小传播范围，不能以近似结果冒充精确 v4。

## JS 一致性

提交内夹具由 `tools/export_ckt_v4_kernel_fixture.js` 直接调用权威 `tools/ckt_v4_model.js` 生成，覆盖：

- 两个定向联合池案例；
- 传统 21×21 与四码顶各 8 个固定种子的随机碰撞案例；
- 每项终止码、码长、辅码数、名次、候选池和运动时间；
- 单字、二字词、三字词、四字词四轨的全部汇总字段；
- 增量更新、全量重算与回滚一致性。

真实语料门槛使用被忽略的大夹具。JS 只导出原始阶段行和预期四轨，Rust 独立读取同一上游角色表并重做竞争：

| 方案 | 合约 | 模式 | 行数 | 结果 |
|---|---|---:|---:|---|
| S005 | 21×21 | 键道 | 289,644 | 全字段一致 |
| S005 | 21×21 | 三拼 | 289,649 | 全字段一致 |
| L600 | 四码顶 | 键道 | 289,644 | 全字段一致 |
| L600 | 四码顶 | 三拼 | 289,649 | 全字段一致 |

比较容差为绝对 `1e-8` 或相对 `1e-11` 中较大者。合成夹具逐项使用 `1e-12`。

真实增量冒烟把两个二字词的完整阶段路径互换，随后分别执行组件重算、全量重算核验、回滚和再次全量核验，四组均一致：S005 键道/三拼各只闭合 8 行，L600 键道/三拼各闭合 179 行；总语料行数不变。该案例证明真实联合池上的更新与回滚通路正确，但不能代表未来一次声韵键交换的影响规模。

## 本机阶段性测量

在当前 Ryzen 9 7945HX / 约 32 GB 内存机器上：

- 旧 Node 单个 S005 正向评分：约 11.1 秒，峰值工作集约 1,749 MiB；
- Rust release 读取 139 MB 的 S005 双模式 JSON 夹具并独立评分：约 2.88 秒，峰值约 556 MiB；
- Rust 同时读取 285 MB 的 S005+L600 四模式夹具：约 5.76 秒，峰值约 1,234 MiB。

阶段 2 紧凑二进制夹具不再经过大 JSON，并按方案/模式逐块释放：

- S005+L600 四块由 271.7 MiB JSON 降至 68.6 MiB；
- Rust release 全量读取和评分约 3.5 秒；
- 25 ms 采样峰值工作集约 136 MiB；
- 四轨全部字段及四组真实增量换位/回滚继续一致。

二进制 v1 的布局、来源哈希和稳定枚举见 `CKT_v4_BINARY_FORMAT.md`。

阶段 3 进一步把跨语言行夹具拆成 5.13 MiB 的方案无关语料和约 6 KiB/方案的状态，并让 Rust 原生生成逐行完全相同的联合池。倒排表可把固定拼音码交换直接缩小到相应模板行，再交给精确碰撞组件。格式、验证数据和固定拓扑边界见 `CKT_v4_NATIVE_CORPUS.md`。

阶段 4 在共享语料之上加入规则状态与退火。规则重建后的 21×21 `S005-NF` 和 21×26 `SNF4-M36-AE-07` 均与 JS 冻结行逐行一致。一次全局声韵键交换可能让精确碰撞闭包接近全图；固定走增量曾超过 50 秒仍未完成首步，而直接行阈值的全量回退让 21×21 两步、每步全量审计的冒烟约 11 秒完成。细节见 `CKT_v4_ANNEALING.md`。

阶段 5 将邻域扩展到单组/单韵母变动和空闲键引入，并把固定拓扑 ID 校验从 `O(kN)` 修正为 `O(k)`。同一单韵母案例由约 18.6 秒降至 2.5 秒。支持边界、M/D/V 来源及逐类审计见 `CKT_v4_SEARCH_NEIGHBORHOOD.md`。

## 复现

```powershell
# 受版本控制的小型 JS/Rust 逐项一致性
just ckt-v4-rust-verify

# 被忽略的真实语料夹具与两方案逐轨验证
just ckt-v4-binary-fixture "S005,L600"
just ckt-v4-binary-verify
just ckt-v4-binary-incremental-smoke

# 严格静态检查
cargo clippy --manifest-path research/ckt-v4-core/Cargo.toml --all-targets -- -D warnings

# 阶段 4 单线程退火与恢复
just ckt-v4-native-corpus
just ckt-v4-anneal "S005-NF" 100 "research/checkpoints/S005-NF-v4.json"
just ckt-v4-anneal-resume "S005-NF" 100 "research/checkpoints/S005-NF-v4.json"

# 阶段 6B 前沿写入/归并和低内存断言
just ckt-v4-frontier-smoke
just ckt-v4-frontier-memory-smoke
```
