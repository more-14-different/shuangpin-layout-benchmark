# 键位图声母位移 link 配色

## 真源与产物

键位图的声母位移配色以 [`tools/keymap_link_colors.js`](../tools/keymap_link_colors.js) 为唯一真源。`a7_CKT_R11.html` 是被 Git 忽略的本地发布产物，不得继续手改其中的配色常量、图例或检查逻辑。

运行 `node tools/sync_keymap_link_colors.js`，会把真源生成的常量、图例和运行时链式检查注入 `a7_CKT_R11.html`。运行 `node tools/sync_keymap_link_colors.js --check` 只检查产物是否为最新，不写文件。同步是幂等的。

运行 `node tools/audit_keymap_link_colors.mjs` 会用无头 Edge 逐一渲染发布页中的全部方案；任一方案无法求解、任一键上关系低于阈值或页面出现脚本异常都会以非零状态退出。可用 `--html` 和 `--edge` 指定其他发布页与浏览器，或通过 `EDGE_PATH` 指定浏览器。

带调方案额外通过 `tools/toned_keymap_render_audit.js` 验证最终 SVG：逐条检查
源键与迁入标签的实际前景色，并把 ØW/ØY 的目的键和真实带调码表核对。
只通过抽象配色图不能证明导入语义完整；漏掉 W/Y 会让旧审计少检查两条链。
`tests/toned-contract-audit.browser.mjs` 故意删去 zero-W 或改错 W 键颜色，
确认两者都会被拒绝。计数是渲染并检查过的方案数，不是对所有视觉属性的保证。

## 显示语义

传统单字母声母离开同名字母键时，来源键帽字母改为细体，来源键帽和目标键上的声母标签使用同一种高饱和度 link 色；目标声母仍保持粗体和下划线。每条位移 link 独立着色，同一张图中的 link 前景色不得重复。真源为各声母定义首选色，并提供受控的高饱和候选色池；每张键位图按自己的位移邻接关系确定性求解，首选色冲突时才沿链换色。

W/Y 零声母位移遵循同一 link 关系，但只从受控的柔和莫兰迪样式池中选择，并同步改变目标零声母卡片的背景色和虚线边框色。W 与 Y 同时位移时强制使用不同样式。A/E/O 零声母不进入 link 配色，继续使用常规样式。

未发生同名声母位移的键帽保持粗体和默认前景色。来访声母不得改变目标键帽本身的颜色；例如 q 迁入 F 键时，只给来源 Q、目标 q 着同色，F 仍按 f 是否留在原键决定样式。

## 链式色差约束

只要某键的键帽字母或该键上的声母标签有一方属于位移 link，两者都必须满足不小于 `0.18` 的 OKLab 欧氏色差。检查面向键上的关系而不是若干硬编码示例，因此会自然形成链式约束：

- X 键帽因 x 位移而着色时，必须与 X 键上的 ch 标签保持大色差；
- x 位于 Y 键时，x 的 link 色必须与 Y 键帽当前的前景色保持大色差；
- 若 Y 也发生零声母位移，Y 的莫兰迪 link 色继续参与上一条检查；若 Y 未位移，其默认色仍参与检查；
- W/ØW、Y/ØY 与普通传统声母使用同一阈值，只有 A/E/O 零声母明确排除。

生成块中的 `resolveKeymapLinkColors` 会先把当前方案转换为 link 邻接图，以有界、确定性的 DSATUR 回溯着色求解；`validateKeymapLinkContrast` 随后按实际方案语义复核全部键上关系。[`tests/keymap-link-colors.test.mjs`](../tests/keymap-link-colors.test.mjs) 检查配色真源、旧近似配色的拒绝行为、同步幂等性，以及本机发布产物是否最新；[`tools/audit_keymap_link_colors.mjs`](../tools/audit_keymap_link_colors.mjs) 负责全量方案的浏览器审计。
